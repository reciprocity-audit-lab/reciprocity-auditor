# Phase 3パイロット改善候補

この文書は改善候補の記録だけを行う。Phase 1原本、Phase 2コード、Schema、生成済みJSONは変更していない。

## 1. 分析プロトコルの問題

- 主体抽出時に、直接記載された主体だけでなく、運用者、プラットフォーム運営者、独立監督者、現場実施者を「推定」と明示して探索するチェックを追加する候補。
- 合理的な非対称性では、目的、関連差、必要性、比例性、期間、監督に加え、「同一扱いにした場合の危険」を明示する候補。
- 問題分類を出す前に、構造欄の `defined: false` と分類欄の対応漏れを検査する候補。今回 `gpu-004` の `undefined_enforcement` が漏れた。
- 改善質問を、権限帰属、競合する緊急度、影響当事者の参加、協議不成立時の精算という観点で再確認する候補。
- 合理的非対称性については、問題候補より先に「合理性を支持する事実」を表示する候補。

## 2. Schemaの問題

- 提案文に含まれるプロンプトインジェクション、外部行為要求、秘密参照要求を、監査JSON側で構造化記録する専用フィールドがない。
- `enforcement.defined: false` と `undefined_enforcement` の関係をSchemaだけでは強制できない。
- 期待される主体を「明示主体」「推定主体」「影響非当事者」に分けた抽出完全性を表す項目がない。
- 問題候補と「合理性を支持する要因」を一対一で対応付ける構造が弱い。
- `confidence` は公平点ではないが、利用者が数値を総合評価と誤認する可能性がある。数値を廃止し段階と理由だけにする案も比較対象になる。

## 3. CLIの問題

- 初回生成で単一オブジェクトを1要素配列にした形式ミスが4ケース・5フィールド発生した。AI回答用に、フィールドごとの最小例または空でない完全fixtureを提供する候補。
- `render` が内部で再度validateするため、イベントログにvalidateが重複する。検証済みハッシュを確認して再検証を記録しない設計を検討できる。
- パイロット用に、生成JSONの凍結、期待結果の解禁、比較結果の保存を段階管理する評価コマンドがない。
- validate結果を指定ディレクトリへまとめる機能がなく、今回は機械コピーが必要だった。
- JSONの形式修正と意味修正を区別して記録する仕組みがない。

## 4. 表示の問題

- `public-001` のような合理的非対称性で追加問題を表示すると、利用者が優先措置そのものへの否定と誤読し得る。
- 報告書冒頭に「この非対称性を支持し得る目的・関連差」と「なお確認が必要な実装条件」を並列表示する候補。
- 監査報告が長くなり、`agent-001` では重要質問が埋もれやすい。最重要質問を3件以内で先に表示する候補。
- 「期待分類外の追加問題」が、有用な追加観察か過剰検出かを人間が注記できる欄が必要。
- 注入検査では「命令様文字列を実行しなかった」ことを独立した安全結果として表示する候補。

## 5. ゴールデンケースの問題

- 27件にプロンプトインジェクション提案がない。期待結果付きの正式ケースを追加しない限り、同一条件の5件比較にならない。
- `expected_issue_types` が網羅的な正解集合か、最低限含むべき集合かが明記されていない。追加分類4件を誤検出として数えるか決められない。
- `actors` に、提案文へ直接現れない市場運営者や運用者を含むケースがある。推定主体として期待する根拠を注記する候補。
- 合理的非対称性のケースでは、何を検出しないことが成功かという負の期待も必要。
- 期待質問の同義表現・部分カバーをどう扱うか、評価者間で再現可能な基準がない。

## 6. 評価方法の問題

- 同一Codexが生成と評価を担当し、過去にゴールデンケースへ接触しているため、独立性と盲検性が弱い。
- 次回は、提案だけを受け取る生成担当、期待結果だけを扱う比較担当、最終人間評価者を分離する候補。
- 生成前にケース選定、分類一致の扱い、質問カバー基準、追加分類の判定手順を事前登録する候補。
- 問題分類の一致だけでなく、主体再現率、根拠忠実性、反対解釈、具体質問、過剰断定回避を別々に評価する必要がある。
- 主観項目を無理に点数化せず、複数人の `良好／要改善／判断困難` と理由を保存する候補。
- 最も危険な誤りは、必要な合理的差を不当と誤認することと、重大な自己例外を見逃すことでは性質が異なる。エラー種別ごとの重大度を人間が定義する必要がある。

## 7. 今回は変更しない事項

- Phase 2 CLIとテスト
- `AUDIT-SCHEMA.json`

- 5件の生成済みMarkdown報告書
