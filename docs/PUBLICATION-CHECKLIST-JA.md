# 公開前プライバシー確認表

`export-public`の検査は誤公開を減らす補助です。完全な匿名性、秘密情報の完全検出、公開後の削除可能性を保証しません。公開するたびに、生成された公開用フォルダだけを人間が確認してください。

## 公開対象を限定する

- [ ] 元の`work`フォルダではなく、`export-public`が作った出力を対象にしている
- [ ] `review.json`、`state.json`、`events.jsonl`、`review-history`、ログ、一時ファイルが含まれていない
- [ ] 不要なZIP、バックアップ、画面写真、エディター設定を含めていない
- [ ] 元提案やAI回答を公開する権限がある

## 本文とメタデータを読む

- [ ] 本名、個人メール、住所、所属、経歴、電話番号がない
- [ ] Windowsユーザー名や`C:\Users\...`などの絶対パスがない
- [ ] 実DID、ウォレットアドレス、取引情報、別名義との対応情報がない
- [ ] seed、秘密鍵、APIキー、パスワード、Cookie、認証トークンがない
- [ ] 非公開URL、内部ホスト名、環境変数、端末固有情報がない
- [ ] 正確な運用時刻を公開する必要があるか確認した
- [ ] 文体、事例、時系列、ハッシュの再利用による関連付けリスクを確認した

## 監査内容を確認する

- [ ] 提案文と`analysis.json`のケースID・SHA-256対応が正しい
- [ ] `audit-report-ja.md`を人間が読み、原文と明らかに矛盾しない
- [ ] 合理的な非対称性と反対方向の解釈が落ちていない
- [ ] 不足情報を推測で補っていない
- [ ] 善悪、適法性、採否、執行、処罰の最終判断をしていない
- [ ] `reviewed`が監査報告書の確認を意味し、元提案の承認ではないと分かる

## 完全性を確認する

- [ ] `PUBLICATION-MANIFEST.json`を読んだ
- [ ] `SHA256SUMS.txt`と全収録ファイルのハッシュが一致する
- [ ] ZIP内に絶対パス、`..`、入れ子ZIPがない
- [ ] 同じ入力から作った決定的ZIPのハッシュが再現する
- [ ] 公開先の説明文にも既知の限界を記載した

## 公開先に関する限界

GitHubその他の公開サービスは、アカウント、IPアドレス、アクセスログ、投稿時刻などを保持し得ます。ブラウザーのゲストモードやプライベートモードは、端末内の履歴分離には役立ちますが、サービス運営者やネットワーク運営者に対する匿名性を保証しません。DID、仮名、文章、ファイルハッシュを別サービスで再利用すると、公開物同士が関連付けられる可能性があります。

公開後に問題を見つけた場合、履歴や第三者コピーまで完全に消せるとは限りません。迷う項目が一つでもあれば公開を止め、合成データへ置き換えてから再検査してください。
